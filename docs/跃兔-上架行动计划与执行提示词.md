## 3. 主体选择：是否需要注册公司

### 3.1 先确定渠道准入，再决定登记

本人是自然人；有限公司是法人；代表公司办理事务的人是法定代表人。“个人开发者”和“公司法定代表人”是不同身份。

| 路径 | 适用情况 | 要核对的限制 |
| --- | --- | --- |
| 个人开发者 | 产品开发、少量测试，以及符合要求的个人发行 | Apple 卖家显示法定姓名；国内安卓商店逐家确认准入 |
| 个体工商户 | 需要经营主体和营业执照，且目标渠道明确接受 | 不能假定被商店认作企业开发者；不是有限公司的责任隔离方式 |
| 有限责任公司 | 长期运营应用、品牌、合同与合作，目标渠道需要公司主体 | 地址、财税、年报、账户、出资及退出等持续义务 |

一个人作为股东设立的有限公司，与个体工商户、个人独资企业不同。有限公司的责任安排不代表个人在所有情况下均免于责任。

### 3.2 已查到的具体条件

- Apple 允许个人注册，但法定姓名会显示为卖家名称；组织账号需要被认可的法律实体，独资经营者通常按个人注册。[Apple 注册说明](https://developer.apple.com/programs/enroll/)、[组织资格说明](https://developer.apple.com/support/D-U-N-S/)
- 华为开发者联盟当前把个人、个体工商户列在个人开发者适用群体中，不能将云平台的“企业认证”与应用开发者资格混为一谈。[华为认证说明](https://developer.huawei.com/consumer/cn/doc/doccenter-getting-started/hdc-verification-introduction-0000002752607793)
- 荣耀公开审核规范列有不接受个人开发者上传应用的要求；T01 需核对具体渠道的最新正式规则及后台条件。[荣耀审核规范](https://developer.honor.com/cn/doc/guides/100879)
- 新设有限公司一般要求股东按章程在成立之日起五年内缴足认缴出资，注册资本不能随意填写高额数字。[《公司法》第四十七条](https://www.samr.gov.cn/djzcj/zcfg/fl/art/2026/art_9b4263a169cf43c2aba950cfc9ac1af2.html)
- 没有收入不等于可以不申报，须按实际情况履行税务义务。[税务总局说明](https://www.chinatax.gov.cn/chinatax/n810219/n810780/c5252600/content.html)

### 3.3 当前决策建议

1. 开发、真机和模型验证继续，不必等注册公司。
2. 若目标国内安卓渠道要求公司主体，优先评估本人控制的有限责任公司。
3. 若考虑个体工商户，先取得目标渠道对该主体、该应用类别的明确准入依据。
4. 未确认前，不购买所谓“包上架”代办，不借用其他人的开发者账号或主体。
5. 如果成立公司，先核算首年总成本，再调整 5,000 元预算；原预算没有完整覆盖公司运营成本。

注册前还需确认拟注册城市、可用地址、记账申报、年报、银行账户、出资安排与注销成本。公司成立不会自动解决 APP 备案、隐私保护和本地 AI 的发行要求。

## 5. 本地 AI 与服务架构

### 5.1 本地 AI 的首轮候选

- 推理引擎：`llama.cpp`，MIT 许可，评估嵌入原生应用的方案。[项目](https://github.com/ggml-org/llama.cpp)、[许可](https://github.com/ggml-org/llama.cpp/blob/master/LICENSE)
- 中文模型：优先对照 `Qwen3-1.7B` 和 `Qwen3-0.6B` 的量化方案，官方列为 Apache 2.0；实际采用时锁定权重、量化、来源、版本和许可。[Qwen 官方说明](https://qwenlm.github.io/blog/qwen3/)
- 这些只是候选，没有安装、选定或完成实机性能验证。

生成流程：原文先加密保存 → 已开启功能的设备读取当前记录 → 本机生成事实概括、小兔回应、【动作神态】和图片倾向 → 检查输出 → 独立展示或加密缓存。

模型不能把计划当作已发生事件，不能把他人经历当作用户经历，不能补写未出现的人物、地点或心理状态。小兔动作可以自然创作，用户事实必须忠于原文；普通一天无需强行夸奖，难过时不催促振作。长文不能只读开头却声称概括全文。

隐私与可用性要求：

- 不调用在线模型，也不设置自动云端回退。
- 日记内嵌指令当作内容，不赋予工具或网络执行能力。
- 公共模型下载不携带日记；下载版本需校验完整性。
- 不把正文、提示词、生成内容或密钥写进日志与崩溃报告。
- 缓存与原始 Delta 分离，持久缓存须加密；修改记录后能识别过期结果。
- 锁定、退出和删除时取消相关任务并处理缓存。
- 模型失败、内存不足或用户关闭时，写作与保存继续可用。
- 小模型的准确性、速度和最低设备条件由真实评测决定，不能以参数量推导流畅性。

### 5.2 为什么仍然需要服务器

同账号跨设备同步需要在线服务；本地小兔推理不需要 GPU 云服务器。

```text
Flutter 客户端（iOS / Android / Windows）
  ├─ 设备内解锁、编辑、搜索、本地 AI
  ├─ SQLite：密文、待同步队列、加密缓存
  └─ HTTPS：密文与必要元数据
       └─ 境内自托管 Supabase
            ├─ Auth：账号与邮件登录
            ├─ PostgreSQL：密文、版本、归属和删除状态
            ├─ 私有对象存储：加密附件
            └─ Realtime / 服务端函数：同步与账号删除

另设：官网与支持页面、邮件服务、公共模型分发、监控及备份。
```

服务端仍可见账号邮箱、对象标识、IP、请求时间和密文大小等必要元数据；管理员能管理或删除密文，但不应持有解密档案的主密钥。加密不替代备份与运维。

自托管需要自行负责更新、监控和灾难恢复，不能将 Supabase CLI 的本地开发栈直接暴露到公网。[Supabase 自托管说明](https://supabase.com/docs/guides/self-hosting)

### 5.3 备份、损坏与升级

没有系统保证永不崩溃；目标是保存有结果、故障能保住资料、恢复经过演练。

| 场景 | 应有处理 |
| --- | --- |
| 应用退出或断网 | 保留已经保存的本机资料与待同步内容 |
| 多端并发与删除冲突 | 保留版本，不静默覆盖或复活内容 |
| 数据库读取失败 | 保留原文件及相关日志文件，不自动清库 |
| 附件上传中断 | 可重试，不把半成品标为成功 |
| 数据升级失败 | 停止继续修改，提供可恢复状态 |
| AI 故障 | 停止生成，不阻塞写作与保存 |
| 全部解锁途径丢失 | 明确无法解密，客服不能绕过 |

数据库和对象存储分别备份；仅备份 PostgreSQL 不包含附件原件。[Supabase 备份范围](https://supabase.com/docs/guides/platform/backups)

在隔离环境实际恢复，验证账号权限、附件及删除状态；已删除账号不能因恢复备份重新获得有效访问。可先以服务端恢复点不超过 24 小时、恢复时间不超过 4 小时作为待演练目标，不作为现有承诺。

当前记录列表每批展示 20 篇只是渲染分批；客户端最终仍有全量对账、解密行为。发行前以合成规模量测启动、搜索、内存和同步，再决定优化，不上传明文换取搜索便利。
