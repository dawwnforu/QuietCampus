# 每日任务：本地数据库准备

本轮只新增迁移 `202610200002_daily_tasks.sql`，未连接、重置或部署数据库，未启用每日任务界面或撕页动画。迁移不填入示例任务，也不改动已有加密记录。

## 保存什么

`public.daily_tasks` 保存所有用户共用的编辑内容：

| 字段 | 用途 |
| --- | --- |
| `task_date` | 对应的日历日期；每天至多一项 |
| `title` | 标题，去除首尾空白后 1–120 字符 |
| `instructions` | 纯文本说明，去除首尾空白后 1–4000 字符 |
| `estimated_minutes` | 可选的正整数预计分钟数 |
| `published` | 默认 `false`；编辑确认后才可设为 `true` |

有效登录用户只能读取已发布项；匿名、普通用户写入及已开始注销的账号读取均被拒绝。后台维护者以后可通过 Supabase 的受控管理端编辑和发布；不新增前端管理凭据或服务。`service_role` 不得放进客户端。

用户的回答、完成状态及日记不放在此明文共享表。后续接入时应继续使用现有客户端加密记录与同步流程；任务日期的关联信息也留在加密内容中。

## 后续接入约定

客户端按设备本地年月日组成 `YYYY-MM-DD`，精确查询 `task_date`，最多返回一项；不以 UTC 截断日期，以免午夜错日。恢复前台或跨日时重新取当天日期。

尚无发布项或离线时显示可选的自由记录入口，不伪造已发布任务，不阻塞日记。任务说明按纯文本显示，不能直接作为 HTML、脚本或自动执行的联网指令。撕页动画、内容排期维护、私密完成记录和实际客户端查询本轮未接入。

有数据的本地实例先备份，再按现有 Supabase 迁移流程增量应用；不要用 `db reset` 代替迁移。完整 Supabase/Auth/API 联调仍待执行。现有 `npm test` 会在独立内存 PostgreSQL/PGlite 中运行该迁移和权限测试，不接触现有数据库。
